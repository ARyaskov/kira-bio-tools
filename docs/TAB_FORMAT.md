# TAB File Format Support for kira-bt  ## Overview  kira-bt now supports TAB-delimited annotation databases, providing full compatibility with bcftools annotate -a functionality.  ## Features  - **TAB file parsing**: Read tab-delimited annotation files - **Column specification**: Use `-c` to specify column mapping (CHROM,POS,REF,ALT,INFO_FIELDS...) - **Header files**: Automatic detection of `.hdr` files for VCF header metadata - **URL encoding**: Proper handling of special characters (=, ;, :, %) in annotation values - **ANI indexing**: Build high-performance indexes from TAB files  ## Usage  ### Basic Annotation  ```bash kira-bt annotate -a database.tab input.vcf -o output.vcf ```  ### With Column Specification  ```bash kira-bt annotate -a database.tab -c CHROM,POS,REF,ALT,ID,INFO/AC,INFO/AF input.vcf -o output.vcf ```  ### With Header File  If `database.hdr` exists alongside `database.tab`, it will be automatically loaded:  ```bash kira-bt annotate -a database.tab input.vcf -o output.vcf ```  ### Pre-building Index  ```bash kira-bt annotate-index database.tab -o database.ani kira-bt annotate -a database.ani input.vcf -o output.vcf ```  ## TAB File Format  ### Basic Structure  ``` CHROM POS REF ALT ID QUAL INFO_FIELD1 INFO_FIELD2 chr1 10 A T rs123456 999 1,2 1e-10,2e-10 chr1 20 G C rs789012 999 3 3e-10 ```  ### With Header Lines  TAB files can include VCF header lines at the beginning:  ``` ##INFO=<ID=AC,Number=A,Type=Integer,Description="Allele count"> ##INFO=<ID=AF,Number=A,Type=Float,Description="Allele frequency"> chr1 10 A T rs123456 999 2 0.001 ```  ### Column Header Row  Optional column names can be specified with `#CHROM` prefix:  ``` #CHROM POS REF ALT ID AC AF chr1 10 A T rs123 2 0.001 ```  ## Column Specification (`-c`)  The `-c` parameter defines which columns from the TAB file should be used:  ### Standard Columns  - `CHROM` - Chromosome name - `POS` - Position - `FROM`/`BEG`/`BEGIN` - Start position (for ranges) - `TO`/`END` - End position (for ranges) - `REF` - Reference allele - `ALT` - Alternate allele - `ID` - Variant ID - `QUAL` - Quality score - `FILTER` - Filter status  ### INFO Fields  - `INFO/FIELD_NAME` - Adds value to INFO column with key FIELD_NAME - `FIELD_NAME` - Shorthand for INFO/FIELD_NAME  ### FORMAT Fields  - `FMT/FIELD_NAME` or `FORMAT/FIELD_NAME` - Adds FORMAT field  ### Examples  ```bash # Basic columns only -c CHROM,POS,REF,ALT  # With ID and INFO fields -c CHROM,POS,REF,ALT,ID,AC,AF  # Explicit INFO prefix -c CHROM,POS,REF,ALT,INFO/AC,INFO/AF  # Skip columns with dash or dot -c CHROM,POS,-,ALT,ID ```  ## Header Files (.hdr)  Header files contain VCF metadata lines that should be added to the output:  ``` ##INFO=<ID=AC,Number=A,Type=Integer,Description="Allele count in genotypes"> ##INFO=<ID=AN,Number=1,Type=Integer,Description="Total number of alleles"> ##INFO=<ID=AF,Number=A,Type=Float,Description="Allele frequency"> ```  The header file is automatically detected if it has the same basename as the TAB file: - `database.tab` → looks for `database.hdr` - `annotations.tab` → looks for `annotations.hdr`  ## URL Encoding  Special characters in annotation values are automatically handled:  - Input TAB file: `=_and_%_and_;_work` - Decoded internally: `=_and_%_and_;_work` - Encoded in VCF INFO: `%3D_and_%25_and_%3B_work`  This ensures proper VCF format compliance while preserving the original values.  ## Performance  TAB file indexing creates ANI indexes with the same performance characteristics as VCF indexing:  - **Index build**: 200k-1M variants/second - **Query speed**: 5-15M variants/second (BGZF output) - **Memory usage**: ~21 bytes per variant in index  ## Compatibility with bcftools  kira-bt aims for 98%+ compatibility with bcftools annotate:  ```bash # bcftools bcftools annotate -a db.tab -c CHROM,POS,REF,ALT,ID,AC,AF input.vcf  # kira-bt (equivalent) kira-bt annotate -a db.tab -c CHROM,POS,REF,ALT,ID,AC,AF input.vcf ```  ## Testing  Run the test suite to verify TAB functionality:  ```bash chmod +x run_tests.sh ./run_tests.sh ```  This compares kira-bt output against bcftools reference files in `tests/bcftools/`.  ## Troubleshooting  ### Index not found  If you see "ANI index not found", kira-bt will automatically build it from the source TAB file. To avoid this on repeated runs, pre-build the index:  ```bash kira-bt annotate-index database.tab ```  ### Column mismatch errors  Ensure your `-c` specification matches the number and order of columns in your TAB file. If no `-c` is specified, kira-bt will: 1. Use column names from `#CHROM` header row if present 2. Otherwise default to `CHROM,POS,REF,ALT` plus auto-numbered fields  ### URL encoding issues  If special characters (=, ;, :) appear incorrectly in output, ensure your TAB file uses proper URL encoding for these characters in the input.
